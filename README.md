# fyto

轻量的图片浏览器，基于 [void Image Viewer](https://github.com/voidtools/voidImageViewer) 开发，采用 MIT 许可证。

支持中文界面、EXIF 侧边栏、标准/精简模式、透明图片棋盘背景和多显示器窗口适配。

## 安装和使用

Windows 10/11 x64 使用安装程序。macOS 12 及以上可下载 Universal DMG，打开后把 fyto.app 拖入「应用程序」。同一份包支持 Apple 芯片和 Intel，应用内更新使用 Universal ZIP。

标准模式的图钉位于右上角最小化键左侧。极简模式下，鼠标滑过图片时图钉会出现在图片右上角。白色线框表示普通窗口，实心白色表示已置顶。Windows 任务栏和 macOS Dock 均隐藏运行图标。再次启动 fyto 或打开图片可找回已隐藏的窗口。

### Windows

下载 Release 中的 `fyto-Setup-版本号.msi` 并运行。也可以解压同名 ZIP 后运行其中的 MSI。支持 Windows 10/11 x64。升级沿用原安装目录和设置。首次打开 fyto 后，可在帮助菜单中设置图片格式关联。

首次使用默认精简模式，之后沿用上次关闭时保存的显示模式。从文件管理器打开图片时使用 Windows 主显示器，默认以图片长边 1980 像素计算窗口尺寸，短边保持原图比例；屏幕可用区域不足时，横图和竖图使用同一个可容纳两种方向的长边上限。安装完成后的空窗口仍保持 16:10 横向比例。

精简模式下只显示图片。鼠标位于图片上时，顶部居中显示文件名，字体和位置与标准模式一致，底部居中显示无边框的播放或暂停键，右下角显示原图分辨率；文件名和分辨率带有轻微淡入淡出，移开鼠标后播放键隐藏、文字淡出。标准模式也使用同样的悬浮播放键和分辨率，所有模式均取消固定的底部播放栏。

窗口起初随图片比例适配。手动拖动边缘或边角后，窗口宽高可自由调整，翻图时沿用手动调整后图片的长边，窗口边框重新贴合图片；横图、竖图和方图按同一长边显示。全屏、最大化和分屏状态下可拖动或从边角恢复后调整窗口。拖动退出全屏后，切换下一张仍保持窗口状态。

| 按键 | 功能 |
| --- | --- |
| 1 | 显示/隐藏菜单栏，切换标准与精简模式 |
| A | 显示/隐藏 EXIF 侧边栏 |
| Esc | 退出 |
| 鼠标中键 | 切换适应窗口与 100% 大小 |

精简模式可拖动未放大的图片来移动窗口；放大到超出窗口时保留原有图片平移。全屏、最大化、分屏或窗口撑满屏幕宽度或高度时，拖动顶部会恢复默认长边 1980 的普通窗口并继续移动，屏幕不足时使用共同长边上限；放大后的图片也支持从顶部拖拽恢复，单击或轻微晃动不会触发恢复。播放键沿用原来的播放、暂停、间隔和翻图逻辑。

### macOS

可在 Finder 中打开图片，或将图片拖入窗口。方向键翻图，1 切换显示模式，P 播放或暂停，A 打开或关闭 EXIF 侧栏，Control+← 和 Control+→ 旋转显示，Command+M 隐藏窗口。右键菜单提供同样的操作。

## 手动更新

macOS 可从标准模式的菜单或图片右键菜单进入 **帮助 → 检查更新**。确认安装后，fyto 下载并校验正式版安装包，替换可写位置中的 fyto.app，重启后恢复当前图片。1.0.0.35 需要先手动换装支持更新的版本。

### Windows

点击 **帮助 → 检查更新**。软件不会在启动时或后台检查，也不会主动弹出更新提示。发现更高版本时，下载 MSI 并校验 SHA-256，按 Windows 安装程序提示完成升级后重新打开 fyto。安装需要允许 Windows 管理员权限提示；取消权限提示会中止更新。更新检查需要 .NET Framework 4.8、网络连接和可访问的 GitHub 正式 Release。

默认更新仓库为 [heytoby/fyto](https://github.com/heytoby/fyto)。也可在 fyto 设置目录创建 `updates.ini`：

```ini
[updates]
repository=heytoby/fyto
```

更新程序通过 GitHub 的公开接口读取正式 Release。私有仓库的下载需要先在浏览器登录并具备仓库权限，软件内的更新检查无法读取私有仓库。没有可访问的正式版本、离线或校验失败时，软件保留当前版本。

## 构建与发布

参见 [发布指南](PUBLISHING.zh-CN.md) 和 [构建说明](BUILD-fyto.md)。`scripts/Build-Release.ps1` 生成 Windows MSI、旧版更新器兼容 EXE、ZIP、源码包和 SHA256SUMS。先在构建分支打包并检查 Windows 安装文件，再将已验证的同一批构建产物发布到 GitHub。

macOS 构建使用 Xcode 命令行工具运行 macos/Build-App.sh。
